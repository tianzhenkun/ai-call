# 通用浏览器坐席中心 V1 设计

最后更新：2026-07-17

## 1. 文档定位

本文档定义 AI Call 项目内“通用浏览器坐席中心”第一版的产品与技术边界。第一版服务于以下四类固定业务场景的 AI 外呼转人工：

- 合同审核；
- 跨境文书；
- 海外获客；
- 地理产品。

坐席中心暂时作为当前项目中的独立模块建设，复用现有登录体系、数据库、LiveKit Room、`ai_call_handoff`、通话记录、录音、对话和事件能力；模块边界保持独立，后续允许整体迁出。

本文档只做设计，不包含实现。

## 2. 目标与成功标准

### 2.1 目标

1. 在线坐席能够看到自己有权限接听的待转人工电话。
2. 多名坐席同时点击接听时，只有一人能够认领并加入通话。
3. 同一坐席同一时间最多处理一通人工电话。
4. 坐席通过浏览器和耳麦加入客户所在的 LiveKit Room。
5. 坐席接入前能够看到 AI 交接摘要、客户上下文和必要对话。
6. 通话结束后必须登记话后结果，必要时创建统一人工跟进任务。
7. 浏览器断线、客户挂机、坐席未接入、服务重启等异常均能确定收敛。
8. 通话、抢单、状态变化和跟进操作可查询、可审计、可解释。

### 2.2 成功标准

- 同一 `handoff_id` 不会被两个坐席同时接通。
- 同一 `agent_id` 不会同时占用两个非终态转人工任务。
- `accepted` 与真实媒体 `connected` 明确区分。
- 坐席断线后可以在限定时间内恢复，超时后不会永久占用任务。
- 客户挂机后，通话、转人工、坐席占用和等待音均能收敛。
- 选择“需要跟进”后一定存在对应跟进任务，不出现半成功。
- 普通坐席无法查看无权限业务、完整电话号码或其他坐席的私有任务。

## 3. 范围

### 3.1 V1 包含

1. 复用现有登录用户作为可信坐席身份。
2. 坐席档案、启停和可接业务范围。
3. 上线、暂停、下线、心跳和服务端在线状态。
4. 浏览器麦克风、扬声器和网络预检。
5. 按业务权限过滤的公共待接池。
6. 新任务声音、桌面通知和页面提示。
7. 服务端事务式原子抢单。
8. LiveKit 浏览器接听、真实接通确认和断线重连。
9. 客户资料、AI 交接快照、对话和录音状态。
10. 客户挂机与坐席主动结束通话。
11. 强制话后处理。
12. 四类业务共用的人工跟进任务。
13. 再次系统外呼、联系尝试、延期、转交、完成和关闭。
14. 基础主管异常处理、操作审计、状态补偿和运营指标。

### 3.2 V1 不包含

- SIP 呼入；
- SIP 话机或 Linphone 坐席；
- 自动分配和复杂排队算法；
- 技能等级、坐席评分和预测式路由；
- 排班、考勤和绩效工资；
- 监听、耳语、强插、保持、三方通话；
- 坐席之间的在线转接；
- 自动质检和完整 CRM；
- 合同、文书、销售或交付业务流程管理；
- 企业微信、短信和邮件自动触达；
- 复杂实时运营大屏；
- 可视化工作流设计器。

## 4. 核心设计决策

### 4.1 建设形态

采用“项目内独立模块、逻辑边界先隔离、物理部署暂不拆分”。

坐席中心负责：

- 坐席身份扩展和业务权限；
- 坐席在线状态；
- 待接池和原子认领；
- 浏览器人工通话；
- 话后处理；
- 人工跟进；
- 坐席操作审计和管理视图。

现有 AI Call 引擎继续负责：

- AI 外呼和四类场景；
- 转人工请求事实；
- LiveKit Room 和音频；
- 录音、对话和事件；
- 通话结束和通话后分析。

### 4.2 接听方式

采用公共待接池。符合业务权限且状态为 `available` 的坐席都能看到任务，谁先完成服务端原子认领，谁获得接听权。

前端按钮置灰只改善体验，不能作为并发控制依据。最终归属以数据库事务提交结果为准。

### 4.3 身份与终端

- 身份复用现有用户登录体系，`user_id` 是稳定身份来源。
- 浏览器是 V1 唯一人工接听终端。
- LiveKit Token 只在认领成功后签发，并绑定 `agent_id`、`handoff_id` 和 `device_session_id`。

### 4.4 跟进边界

四类业务共用同一套人工跟进流程。坐席中心只管理“谁在何时通过何种方式再次联系客户以及联系结果”，不管理合同审核、海外获客等业务自身的阶段和交付流程。

业务归属只通过 `business_type + business_id` 关联上游业务对象。

## 5. 信息架构

### 5.1 坐席工作台

工作台是坐席登录后的默认页面。

顶部状态栏显示：

- 离线、空闲、认领中、通话中、话后处理中、暂停；
- 上线接听、暂停接听、下线；
- 麦克风、扬声器、网络和录音状态；
- 当前可接业务；
- 今日接听数、未接数和平均通话时长。

主体分为三栏：

1. 左侧：待接来电池；
2. 中间：当前通话和话后处理；
3. 右侧：客户、业务和 AI 交接上下文。

无通话时，中间显示简洁空状态，不展示内部 Room、Token、Participant 等调试字段。

### 5.2 待接来电池

每条任务显示：

- 等待时长和 SLA 提示；
- 业务类型；
- 脱敏客户姓名和号码；
- 转人工来源和原因；
- AI 通话持续时间；
- 一句话 AI 交接摘要；
- 接听按钮。

列表默认按等待时长从长到短排序，只展示坐席业务权限范围内且客户仍在线的任务。

### 5.3 当前通话

接通后显示：

- 客户与业务类型；
- 人工通话时长；
- 麦克风静音与恢复；
- 音频设备切换；
- 网络质量和重连提示；
- 录音状态；
- 结束人工通话。

结束通话是危险操作，必须明确说明会断开客户电话并二次确认。前端不能只断开本地 LiveKit 连接。

### 5.4 上下文区

坐席接入前即可查看：

- 客户基础资料；
- 业务类型和来源业务标识；
- 本次使用的场景、开场白和提示词版本名称；
- 转人工原因及客户原话；
- 冻结的 AI 交接快照；
- 最近若干轮对话；
- 完整对话展开入口；
- 必要业务资料卡。

交接快照在转人工触发时冻结，至少包含客户诉求、已确认信息、AI 已做事项、待解决问题和风险提示。

### 5.5 我的跟进

统一展示：

- 今日待跟进；
- 即将到期；
- 已逾期；
- 我负责的全部任务；
- 已完成与已关闭任务。

支持按业务类型、计划时间、优先级和状态筛选。

### 5.6 管理页面

V1 包含：

1. 坐席管理：启停、业务权限和当前状态；
2. 通话与转人工记录：坐席、等待时间、结果、录音和对话；
3. 跟进任务管理：查询、转交和异常处理；
4. 基础配置：接听 SLA、认领接入期限、重连期限、话后结果选项；
5. 基础运营统计：在线状态、等待量、接通率和异常率。

## 6. 坐席状态机

```text
offline
  -> available    上线且设备预检成功

available
  -> claiming     原子认领成功
  -> paused       主动暂停
  -> offline      主动下线或心跳过期

claiming
  -> in_call      LiveKit Participant 与麦克风发布均确认成功
  -> available    接入失败且仍保持上线
  -> paused       接入失败且坐席已选择暂停

in_call
  -> reconnecting 媒体断开或通话页失联
  -> wrap_up      客户挂机或通话正常结束

reconnecting
  -> in_call      限期内恢复
  -> wrap_up      客户已挂机或通话已结束
  -> available    重连失败、任务重新进入待接池

wrap_up
  -> available    提交话后结果
  -> paused       提交后暂停
  -> offline      提交后下线
```

规则：

- `in_call`、`reconnecting`、`wrap_up` 不能认领新任务；
- 坐席运行状态以服务端为准；
- 空闲坐席心跳连续约 30 秒过期后转为 `offline`；
- 通话中失联先进入重连窗口，不立即释放通话；
- 同一账号允许打开多个页面，但同一时间只有一个 `device_session_id` 拥有媒体控制权。

## 7. 转人工与认领状态机

继续复用现有 `ai_call_handoff`：

```text
requested
  -> accepted     坐席原子认领成功
  -> expired      客户总等待超时
  -> canceled     客户挂机或业务取消

accepted
  -> connected    坐席真实加入 Room 且媒体就绪
  -> requested    接入失败，客户仍在线且总等待未超时
  -> expired      总等待超时
  -> canceled     客户挂机
  -> failed       不可恢复的接入错误

connected
  -> completed    人工通话正常结束
  -> requested    坐席重连失败，但客户仍在线且可继续等待
  -> canceled     客户挂机
  -> failed       不可恢复的通话异常
```

### 7.1 原子认领

服务端在同一数据库事务内：

1. 锁定并校验 `ai_call_handoff.status = requested`；
2. 校验客户仍在线、Room 存在且任务未过期；
3. 锁定并校验坐席状态为 `available`；
4. 校验坐席具备该业务权限；
5. 更新 handoff 为 `accepted` 并绑定坐席与设备；
6. 更新坐席为 `claiming` 并绑定 handoff 与 call；
7. 提交成功后再签发 LiveKit Token。

任一条件不满足则整个事务失败。冲突统一返回稳定业务错误，不泄露数据库异常。

### 7.2 `accepted` 不等于 `connected`

浏览器完成以下步骤后才能请求媒体就绪确认：

1. 加入 LiveKit Room；
2. 成功发布麦克风轨道；
3. 准备好播放远端声音。

后端还需核验 LiveKit Participant，核验成功后才写 `connected`。

### 7.3 接入和重连期限

- 认领后建议在 15 秒内完成媒体接入；
- 通话中断后建议提供 15 秒重连窗口；
- 两个期限都不能突破客户的转人工总等待期限；
- 接入或重连失败后，若客户仍在线且总等待未超时，任务可以重新进入待接池；
- AI 在整个转人工和人工通话阶段保持挂起，避免与坐席同时发声。

## 8. 设备检测和通知

### 8.1 上线前设备检测

坐席进入 `available` 前必须通过：

- 麦克风授权；
- 麦克风输入电平检测；
- 扬声器选择与测试；
- 浏览器音频播放授权；
- LiveKit 网络连通性检查；
- 浏览器能力检查。

失败时保持非空闲状态，并给出可操作的修复提示。

### 8.2 待接提醒

V1 使用 SSE 或 WebSocket 推送任务进入、被认领、取消和过期；定时查询作为断线兜底。

提醒方式：

- 页面声音；
- 浏览器桌面通知；
- 页面标题和未读数；
- 超过 SLA 的视觉提醒。

坐席暂停、通话中或话后处理中不播放新任务声音。

## 9. 话后处理

客户挂机或坐席结束人工通话后，坐席进入 `wrap_up`，提交话后结果后才可继续接听。

统一处理结果：

- `resolved`：已解决；
- `follow_up_required`：需要跟进；
- `customer_refused`：客户拒绝；
- `invalid_contact`：联系方式无效；
- `transferred_offline`：已转线下处理；
- `other`：其他。

话后处理至少记录：

- 实际接听坐席；
- 处理结果；
- 人工摘要；
- 是否需要跟进；
- 提交时间。

若选择需要跟进，则同一事务内创建跟进任务，避免话后结果与跟进任务不一致。

## 10. 统一人工跟进

### 10.1 跟进含义

跟进指坐席后续通过电话、微信、邮件或其他方式再次联系客户，例如客户要求稍后再打、无人接听、发送资料后确认、内部查询后回复或转交其他人员。

跟进模块不管理四类业务自身的业务阶段。

### 10.2 状态

```text
pending
  -> processing
  -> completed    已完成本次跟进目标
  -> closed       客户拒绝、联系方式无效或无需继续

processing
  -> pending      需要再次联系、延期或转交
  -> completed
  -> closed
```

逾期由 `scheduled_at < 当前时间` 且任务非终态计算，不作为主状态。

### 10.3 跟进结果

- 已解决；
- 需要再次联系；
- 客户暂不方便；
- 无人接听；
- 客户拒绝；
- 联系方式无效；
- 已转交其他人员；
- 无需继续跟进。

### 10.4 再次电话联系

坐席点击“呼叫客户”后，服务端根据受控客户资料发起新外呼，不向普通坐席暴露完整号码。新外呼生成新的 `call_id`，并通过 `follow_up_id` 关联跟进任务。

接口受理只表示外呼任务创建成功，不代表客户已接通。

### 10.5 重复任务提示

创建跟进任务时，如果同一客户和业务已有未完成任务，页面提示坐席选择：

- 更新已有任务；
- 关联已有任务；
- 明确创建新任务。

V1 不自动合并任务。

## 11. 数据设计

### 11.1 `ai_call_agent_profile`

| 字段 | 说明 |
|---|---|
| `id` | 雪花主键 |
| `user_id` | 现有用户 ID，唯一 |
| `agent_code` | 坐席编号，唯一 |
| `display_name` | 展示名称 |
| `enabled` | 是否启用 |
| `max_concurrent_calls` | V1 固定为 1 |
| `created_at` / `updated_at` | 时间 |

### 11.2 `ai_call_agent_business_scope`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `agent_id` | 坐席 ID |
| `business_type` | 业务编码 |
| `enabled` | 是否允许接听 |

对 `(agent_id, business_type)` 建唯一约束，不建物理外键。

### 11.3 `ai_call_agent_presence`

| 字段 | 说明 |
|---|---|
| `agent_id` | 坐席 ID，唯一 |
| `status` | 坐席运行状态 |
| `active_handoff_id` | 当前 handoff |
| `active_call_id` | 当前 call |
| `device_session_id` | 媒体控制设备 |
| `heartbeat_at` | 最近心跳 |
| `status_changed_at` | 状态变化时间 |
| `version` | 并发版本 |

### 11.4 `ai_call_handoff` 调整

复用现有表，建议增加：

| 字段 | 说明 |
|---|---|
| `claim_expires_at` | 本次坐席接入期限 |
| `accepted_device_session_id` | 获得接听权的设备实例 |

`expires_at` 继续表示客户转人工总等待期限。

### 11.5 `ai_call_after_call_work`

| 字段 | 说明 |
|---|---|
| `work_id` | 话后处理 ID |
| `call_id` | 通话 ID |
| `handoff_id` | handoff ID，唯一 |
| `agent_id` | 接听坐席 |
| `disposition_code` | 处理结果 |
| `summary` | 人工摘要 |
| `needs_follow_up` | 是否需要跟进 |
| `submitted_at` | 提交时间 |
| `version` | 并发版本 |

### 11.6 `ai_call_follow_up_task`

保存客户引用、业务引用、来源 call/handoff、负责人、状态、联系方式、原因、优先级、计划时间、摘要、关闭原因、版本和终态时间。

### 11.7 `ai_call_follow_up_attempt`

每次联系新增一条，保存操作坐席、联系方式、结果、关联新 call、备注、实际联系时间和下次计划时间。历史尝试只新增，不覆盖。

### 11.8 数据约束

- 不使用物理外键；
- 不使用数据库专属 JSON 类型；
- bigint ID 返回前端时统一转字符串；
- 电话号码、Token、完整对话不进入普通操作日志；
- 关键查询建立普通索引和业务唯一约束；
- 所有表是否接入租户能力，以当前 AI Call 与宿主用户体系的实际租户边界为准，实施前必须明确，不能在查询中零散手写租户条件。

## 12. 接口设计

### 12.1 坐席工作台

```http
GET  /ai-call/agent-console/bootstrap
POST /ai-call/agent-console/presence/online
POST /ai-call/agent-console/presence/pause
POST /ai-call/agent-console/presence/offline
POST /ai-call/agent-console/presence/heartbeat
GET  /ai-call/agent-console/handoffs/pending
POST /ai-call/agent-console/handoffs/{handoffId}/claim
POST /ai-call/agent-console/handoffs/{handoffId}/media-ready
POST /ai-call/agent-console/handoffs/{handoffId}/reconnect-token
POST /ai-call/agent-console/handoffs/{handoffId}/complete
PUT  /ai-call/agent-console/calls/{callId}/after-call-work
```

`claim` 必须支持幂等键。成功只表示认领成功和媒体连接开始，不表示人工已接通。

### 12.2 跟进

```http
GET  /ai-call/agent-console/follow-ups
GET  /ai-call/agent-console/follow-ups/{followUpId}
POST /ai-call/agent-console/follow-ups/{followUpId}/attempts
POST /ai-call/agent-console/follow-ups/{followUpId}/call
POST /ai-call/agent-console/follow-ups/{followUpId}/transfer
POST /ai-call/agent-console/follow-ups/{followUpId}/complete
POST /ai-call/agent-console/follow-ups/{followUpId}/close
```

再次外呼接口只表示任务已创建，最终通话状态通过 `call_id` 查询。

### 12.3 管理端

```http
GET  /ai-call/admin/agents
POST /ai-call/admin/agents
PUT  /ai-call/admin/agents/{agentId}
PUT  /ai-call/admin/agents/{agentId}/business-scopes
GET  /ai-call/admin/agents/{agentId}/status
POST /ai-call/admin/agents/{agentId}/force-offline
GET  /ai-call/admin/handoffs
GET  /ai-call/admin/follow-ups
```

强制操作必须区分禁止接新任务、当前通话结束后下线和强制结束当前通话。强制结束必须二次确认并写审计。

### 12.4 错误码

至少提供：

- `HANDOFF_ALREADY_CLAIMED`
- `HANDOFF_EXPIRED`
- `CUSTOMER_NOT_CONNECTED`
- `AGENT_NOT_AVAILABLE`
- `AGENT_SCOPE_MISMATCH`
- `AGENT_ALREADY_IN_CALL`
- `DEVICE_SESSION_CONFLICT`
- `CLAIM_CONNECT_TIMEOUT`
- `MEDIA_NOT_READY`
- `FOLLOW_UP_VERSION_CONFLICT`

错误信息面向坐席说明下一步操作，不直接暴露内部异常。

## 13. 权限与数据安全

1. 普通坐席默认只查看有权限业务的待接任务、自己的通话和自己的跟进任务。
2. 主管按授权范围查看坐席和业务数据。
3. 普通页面只展示脱敏号码，完整号码仅供服务端发起通话。
4. 录音、对话、客户资料和导出分别授权。
5. LiveKit Token 短期有效、按参与者签发，不进入 URL、普通日志或持久化响应缓存。
6. 服务端不能接受前端传入的任意 `agent_id` 作为身份，以当前登录用户为准。
7. 所有启停、权限修改、强制释放、转交和话后结果修订均写审计。
8. 录音告知、保留期限和下载权限由实际业务合规要求确定，实施前作为上线门槛确认。

## 14. 异常场景与恢复

### 14.1 坐席抢单冲突

只有首个事务成功；其他请求返回任务已被接听，并立即从待接池移除。

### 14.2 认领后未接入

到 `claim_expires_at` 后释放坐席。如果客户仍在线且总等待未超时，handoff 回到 `requested`；否则按超时或失败闭环。

### 14.3 坐席通话中断线

保留 15 秒重连窗口。窗口内原坐席保有接听权；超时后根据客户和总等待状态重新入池或结束。

### 14.4 客户挂机

客户挂机优先结束通话，收敛 handoff，停止等待声与录音，释放媒体资源，并让坐席进入 `wrap_up`。

### 14.5 坐席关闭浏览器

不依赖 `beforeunload`。结合 LiveKit Participant 和服务端心跳判断，空闲状态过期后离线，通话状态先进入重连。

### 14.6 服务重启

启动和定时补偿检查：

- accepted 但无坐席 Participant；
- connected 但 Room 已不存在；
- in_call 但无活动通话；
- 通话已结束但坐席仍被占用；
- 话后要求跟进但任务缺失；
- 已过期但仍占用资源的 handoff。

补偿动作必须幂等并记录事件。

### 14.7 录音失败

页面明确显示异常并产生告警，不得继续显示“录音中”。通话是否继续由业务合规策略决定，不能在前端静默决定。

## 15. 刷新与推送策略

- 待接任务和状态变化优先使用 SSE 或 WebSocket；
- 轮询作为推送断线兜底；
- 页面重新加载时调用 `bootstrap` 恢复当前坐席、通话和设备控制权；
- 关键操作后读取服务端最新状态，不仅依赖本地乐观更新；
- 通话结束、录音完成等异步动作必须查询最终状态，受理响应不等于业务完成。

## 16. 幂等与并发

以下操作必须支持幂等键或版本控制：

- 原子认领；
- 媒体就绪确认；
- 结束通话；
- 提交话后结果；
- 创建跟进任务；
- 再次外呼；
- 转交、完成和关闭跟进任务。

坐席状态和 handoff 的关键变更在同一事务完成。跟进任务修改使用 `version`，冲突时要求刷新后重试，不能静默覆盖。

## 17. 基础指标与告警

V1 至少统计：

- 在线、空闲、通话中和话后处理坐席数；
- 当前等待人工客户数；
- 平均和 P95 等待时间；
- 转人工接通率、超时率和取消率；
- 抢单成功和冲突次数；
- 浏览器媒体接入失败率；
- 人工通话异常断线率；
- 需要跟进、即将到期和已逾期任务数；
- 状态补偿次数和失败次数。

以下情况至少记录结构化错误并触发告警：任务长期非终态、坐席占用泄漏、录音失败、重复补偿失败和异常高接入失败率。

## 18. 验收场景

### 18.1 正常流程

1. 坐席通过设备检测并上线。
2. 业务权限范围内的转人工任务进入待接池并触发提醒。
3. 坐席认领成功，获得 Token，真实加入 Room。
4. AI 保持挂起，客户与人工双向通话。
5. 客户或坐席结束通话。
6. 坐席提交话后结果后恢复空闲。

### 18.2 并发流程

1. 两名坐席同时认领同一任务，只有一人成功。
2. 同一坐席同时认领两项任务，只有一项成功。
3. 同一账号双页面操作，只有媒体控制设备能够接入。
4. 重复提交认领、结束和话后结果，不产生重复业务记录。

### 18.3 异常流程

1. 认领后浏览器拒绝麦克风权限，任务按规则释放。
2. 认领后未加入 Room，超过接入期限后释放。
3. 人工通话中断网，期限内重连成功。
4. 重连失败后任务重新入池或按总等待超时结束。
5. 客户在等待、认领或人工通话阶段挂机，状态均正确收敛。
6. 服务重启后能够修复悬挂的 handoff 和坐席状态。
7. 录音失败能够被坐席和管理端识别。

### 18.4 跟进流程

1. 话后选择需要跟进时原子创建跟进任务。
2. 到期和逾期任务正确展示。
3. 再次电话联系产生新的 call 并关联原任务。
4. 未接通后可记录尝试并安排下次时间。
5. 跟进可以转交、完成和关闭，历史尝试不被覆盖。
6. 同客户已有未完成任务时出现重复提示。

## 19. 分阶段交付建议

### V1：可用闭环

- 坐席档案和四类业务权限；
- 设备预检、上线和心跳；
- 待接池、实时提醒和原子认领；
- 浏览器 LiveKit 接入与真实 connected；
- 客户上下文和 AI 交接快照；
- 结束通话、话后处理；
- 统一人工跟进和再次外呼；
- 权限脱敏、幂等、审计和关键补偿；
- 基础管理查询和指标。

### V1.1：运营增强

- 更完整的主管异常处理；
- 更细的提醒规则；
- 录音和对话查询体验；
- 跟进批量转交；
- SLA 报表与告警完善。

### 后续阶段

只有真实需求出现后，再评估自动分配、技能评分、坐席转接、监听质检、SIP 坐席、外部消息渠道和独立服务迁移。

## 20. 后期迁出边界

迁出时，坐席中心继续拥有坐席档案、在线状态、认领、话后处理和跟进数据；AI Call 继续拥有通话、Room、录音、对话和模型生命周期。

双方通过稳定接口或事件交换：

- 待转人工任务创建、取消和过期；
- 认领结果；
- 人工媒体已连接；
- 人工通话结束；
- 客户挂机；
- 通话摘要、录音和最终状态。

V1 不提前建设分布式消息系统，但接口命名、业务 ID 和状态语义必须避免依赖进程内对象，为后期迁移保留清晰边界。
