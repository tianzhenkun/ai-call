# 对话结束与转人工执行边界

## 有效轮次

- 保留 15 个有效客户轮次的既有上限；在客户发言结束、完整转写经审核确认是客户发言、实际提交回复时计数。
- 同一轮的 ASR 分片、重复最终稿、工具续答只计一次。开场白、系统提示和未成功提交的回复不计数。
- 第 15 轮仍要求模型回答客户当前问题，需要时正常查询知识，再礼貌收尾；不直接用固定告别语替换客户问题。
- 结束必须等待最后一轮回复及播放完成。有效转人工请求取消尚未执行的告别，成功挂起 AI 后停止 AI 对话计时。
- 保留原有 240 秒收尾提示、290 秒告别、300 秒安全结束策略。客户继续提问可以打断告别，但不能移除安全结束保护。

## 外呼计时的入口类型

- 运行会话携带真实 `entry_type`：Owner 从通话记录传入，旧 SIP / 网页入口分别传入 `sip_outbound` / `web`。`outbound`、`direct_sip`、`sip_outbound` 使用既有电话通话策略；网页入口不启用无人回应及最长时长保护。
- `caller-` 同时用于 Owner 外呼和网页通话，不能作为电话类型判断依据；仅未携带入口类型的旧会话保留 `sip-` 兼容判断。共用的 SIP 媒体判断也使用同一入口类型。
- 回复播放完成后开始 8 秒无人回应计时，连续两次询问仍无回应时，在第三次超时请求告别，正常等待告别播放完成再调度 `policy_no_response`；240 / 290 / 300 秒时长策略保持不变。这是无人回应兜底，不代表实时识别语音信箱后立即挂断。
- 本地回归覆盖正式外呼 `caller-`、网页 `caller-`、旧 SIP 入口、转写超时后恢复计时、告别播放门控和时长安全结束。供应商与媒体使用隔离替身，尚未完成部署及真实通话验收。

## 客户发言审核与连续离题

- 复用现有 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 及其 DashScope 回退配置。完整 ASR 转写按原文分句，结合业务提示词、最近对话、此前识别的背景声和已有音频观测，区分客户、背景和不确定内容。模型只标记分句来源，客户原话由程序从输入重建，不能使用模型补写的文字授权控制动作。
- 混合发言仅保留已确认的客户分句；无法可靠分开的内容、模型超时、无效结果和缺失最终转写不计轮次，也不能授权结束工具。不确定时简短澄清；明确背景声不触发新业务回复，已有停播则恢复被打断的内容。
- 审核在独立任务中执行，2.5 秒超时；不阻塞模型媒体事件。新发言取消旧审核，迟到结果按发言及 ASR item 校验，结束或转人工时取消任务。未经审核的 ASR 分片不确认语义打断或触发客户控制意图。
- `policy_limit` 只接受连续三个**已提交回复的有效客户离题轮次**及对应转写事件证据。累计客户轮数不能替代连续离题证据；业务回应、通话控制、背景和不确定发言打断离题连续性。15 轮上限与时长保护独立执行。
- `customer_speech_classified` 持久化原转写、客户/背景分句、判断依据、置信度、耗时、异常类型及源事件；`call_policy_customer_turn` 持久化有效轮数和连续离题事件 ID。对话转写保留原始接收时间，审核耗时单独记录。
- 2026-09-21 的两个客户轨录音回放中，`semantic_vad` 仍保留报站内容，并漏掉部分客户回应，故继续使用 `server_vad`。审核抽样耗时不等于线上首句延迟；仍需发布后的真实通话验证。

## 转接事实与播报

- `handoff_tool_requested` 只是请求，不代表数据库已提交，更不代表人工已接通。
- 明确客户转人工工具请求进入执行阶段后，停止该响应的模型音频；既有 generation 校验继续丢弃迟到音频。
- 成功转接由系统提示音接管；等待提示音和等待超时任务只能在请求事务提交后启动，且请求必须仍处于等待/已认领阶段。
- 关闭、回滚及 savepoint 回滚不能把旧回调带到下一次事务。新请求未提交但 AI 已挂起时，走既有 owner-control 以 `handoff_service_unavailable` 结束，避免永久静默。
- 禁用、队列满、创建失败及重试耗尽，按 `toolCallId` 回传给仍存活的模型；重复请求不误报新建成功或失败。
- 等待执行结果超过 10 秒只表示“结果未确认”，不推断为已接通、坐席忙或确定失败；不会取消后台事务或自动重试。
- 模型已关闭时不补发工具回复。异常信息保留在事件中，不将数据库错误正文作为模型指令。

## 展示与验证

通话列表、详情和坐席跟进详情统一优先展示明确的 `endReason`，附加不重复的故障详情；只有没有明确原因时才使用接听类型或旧状态回退。`unknown` 不遮住有信息的故障详情。

本地回归覆盖 ASR 分片、工具续答、最后一轮问题、时长保护、转接结果关联、迟到音频和数据库提交/回滚边界。供应商、电话和媒体在测试中隔离，不能替代真实电话验收，也未改变历史通话记录。

## 普通回复中的转接承诺出声前校验

当前默认入口使用 `AliyunQwenRealtimeProvider` 直接输出模型音频。完整文本审核加独立 TTS 仅保留为隔离候选，未接入默认入口，未部署、未进行真实电话验收。现有客户意图和工具执行校验仍保留，但不能保证拦截普通自由回复中的虚假转接承诺。

2026-10-02 的 20 组配对实测中，候选路径从客户音频结束到播放入口的配对新增耗时中位数为 1574.1 毫秒，且 4 条转接状态问询全部发生输出审核超时。用户要求优先保证商业通话体验，因此撤出默认入口。后续候选只有同时满足拦截效果和低延迟要求，才考虑接入；目前没有已验证达标的替代方案。

### 隔离候选的播报路径

1. `GuardedQwenSpeechProvider` 保留 Qwen 实时音频输入、工具调用及原有 runner，模型仅生成文本。完整短回复经语义审核后进入独立流式 TTS；供应商意外返回原始模型音频时直接报错，不回退播放。
2. 审核复用文本模型配置，区分正常问题、征求意愿和擅自声明转接进展。拒绝整段草稿后最多改写一次，改写也须审核；两次审核共用 2.5 秒期限。无安全改写时使用真实状态话术，审核异常或超时使用明确的暂不可确认话术。审核本身不创建转接请求。
3. 转人工工具的拒绝、确认、失败、未知结果按 `toolCallId` 关联，由服务端直接播报；不请求模型自由续答。事务提交前的挂起事件不能用于宣告已经排队；成功转接继续交给原有等待提示音和人工媒体流程。
4. 只有完整客户发言可以触发意图分类。`转人工` 分片可能继续成为 `转人工了吗`；后者询问已有状态，不授权新建请求。含人工角色词但意图不明确的工具请求先征求确认，例如样本中的 `小人工`、`打人工`；仍复用原有确认及幂等创建流程。
5. 原始草稿从 Qwen 上下文删除，只将选定播报写入；Qwen 会重新分配消息 ID，必须等待服务端返回实际 ID 后才能放行第一段音频。取消时删除未完成播报的上下文，处理迟到确认，关闭 TTS 流并丢弃迟到音频。完成事件在 TTS 完成后发给 runner，继续使用原有播放完成和挂断门控。
6. 草稿、审核结论、选定文本和首段音频耗时分别持久化为 `speech_draft`、`speech_output_reviewed`、`speech_output_selected`、`speech_first_audio`；审核失败记录 `speech_output_review_failed`。对话字幕仅由选定播报生成，不能把草稿当作已经说过的话。播放和录音是否真正到达客户，仍以媒体证据为准。

### 隔离验证参数

- 隔离脚本显式构造 `GuardedQwenSpeechProvider`、审核器和 TTS，默认运行入口不通过 `TTS_*` 配置启用此候选。
- 验证使用 `qwen3-tts-flash-realtime-2025-11-27` 和用户选择的 `Cherry`（芊悦），密钥由现有本地配置读取，不写入实验产物。仅选择性复用了候选实现的 commit 协议，没有合并候选分支。
- 审核器显式传入文本模型地址、密钥和模型；本次 A/B 使用 `qwen-plus`，缺必需配置在 provider 创建时失败。
- Omni 会话的原有 `voice` 参数仍需使用该模型支持的值，不能拿独立 TTS 的 Cherry 代替。本次真实接口验证中 Omni 使用 Tina；实际声音由独立 TTS 决定，记录于 `speech_output_configured` 的 `ttsModel` / `ttsVoice`，不把 Omni 的 voice 当作实际播报音色。

| 真实状态 | 允许的播报行为 |
| --- | --- |
| 建议转人工，仍需客户确认 | 征求确认，不声称已执行 |
| 请求已提交并进入队列 | 告知正在联系人工、请稍候 |
| 坐席已认领，媒体尚未接通 | 保持等待，不宣称已接通 |
| 人工媒体接入确认成功 | AI 退出，由人工继续沟通 |
| 转接失败或结果未确认 | 区分失败与未知，不虚构成功、忙线或回访安排 |

### 验证与边界

- 自动回归覆盖无工具承诺、改写复核、审核超时、TTS 故障、工具结果、事务提交边界、客户插话、迟到音频、迟到上下文确认、真实 runner 的播放入口及对话文本。供应商和媒体隔离测试不能替代真实电话验收；TTS 或模型传输失败进入既有失败清理路径。
- 撤出默认入口前的候选回归：`tests/test_ai_call_guarded_speech.py`、`tests/test_ai_call_handoff_tool_feedback.py`、`tests/test_ai_call_handoff_tool_outcomes.py`、`tests/test_ai_call_phase_a_core.py`、`tests/test_ai_call_phase_b1_records.py` 共 649 项通过。当前测试分别验证默认入口直接输出音频与隔离候选的审核门控，不能将候选测试通过视为默认入口已具有拦截能力。
- 恢复默认语音入口后，运行 `tests/test_ai_call_guarded_speech.py`、`tests/test_ai_call_phase_a_core.py`、`tests/test_ai_call_runtime_conversation_policy.py`、`tests/test_ai_call_runtime_livekit_provider.py`，共 483 项通过；本次修改的 Python 文件 Ruff 与 `git diff --check` 通过。
- 真实供应商接口已验证音频输入转写、文本输出、工具调用及结果回传、上下文删除和重建、Cherry PCM 合成。三条完整播报样本中普通介绍获准，直接及隐含转接承诺被拦截；从请求到第一段可播放音频为 1891 / 2080 / 2091 毫秒。这是小样本接口探测，不是电话链路 p50/p95，也不包含 SIP 播放延迟。
- 真实接口取消测试在第一段音频后取消：只放行 1 段，返回 cancelled，服务端确认删除草稿和本次播报上下文，没有供应商错误。
- 20 组配对供应商接口加 runner 实测使用相同客户输入音频，交替测试旧、新路径，各 20 轮均产生音频；不经过 LiveKit、SIP 或电话。请求到第一段音频中位数为旧路径 620.9 毫秒、候选 2150.5 毫秒；客户音频结束到播放入口中位数为旧路径 2857.7 毫秒、候选 4451.2 毫秒。后一个指标的样本 P95 分别为 3018.8 / 5681.7 毫秒。候选 4 条转接状态问询全部审核超时并使用兜底话术，不能把有音频视为业务回答成功。可复放脚本、结果和分析保留于本地忽略目录 `build/speech-latency-ab-20261002/`。
- 当前没有改造前后真实电话的延迟、成本和误判率对照；后续电话验收还需核对音色、字幕、打断、最终播放及录音一致性。语义审核仍可能漏判，不承诺覆盖任意自由措辞。

技术依据：Qwen-Omni-Realtime 官方文档支持保留音频输入并仅输出文本，文本通过 `response.text.delta` / `response.text.done` 返回。文档支持不替代当前模型版本的实际兼容性验证。[Qwen 官方说明](https://help.aliyun.com/zh/model-studio/realtime)
