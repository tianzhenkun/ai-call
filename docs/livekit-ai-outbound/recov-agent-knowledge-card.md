# Recov Agent 催收智能体知识卡 v1

## 文档定位

本知识卡用于公司综合呼入场景中介绍 Recov Agent 催收智能体，帮助 AI 回答产品定位、适用客户、核心能力、业务流程、合作方式和常见边界问题。

本知识卡不是具体债务人的催收执行话术，不用于生成还款提醒、欠款告知、施压升级或承诺还款沟通。

## 与动态外呼催收的隔离契约

1. 呼入综合接待使用 `sceneCode=inbound_company_reception`。
2. 客户对催收业务感兴趣时，使用 `businessCode=collection` 和本知识卡继续介绍。
3. 现有 `intro_collection` 继续用于外呼催收执行，由 `business_query` 根据具体用户画像动态获取开场白和催收话术。
4. 呼入场景不得加载或引用 `intro_collection` 的债务人画像、欠款金额、账龄、逾期时间、历史承诺、联系人信息和动态催收话术。
5. 客户从催收业务切换到其他业务时，只切换当前业务主题，不重新创建 Room、Qwen Session 或通话记录。
6. 整通呼入记录的 `sceneCode` 保持 `inbound_company_reception`，客户关注的业务通过 `businessCode` 事件和通话后语义结果记录。

## 产品定位

Recov Agent 是面向逾期资产处置和催收运营的 AI 智能体。它围绕数据解析、逾期画像、策略生成、沟通触达、语义分析、人工协同、送达留痕、法律流程衔接和回款确认，把原本分散的人工催收环节组织成可执行、可记录、可复盘的业务流程。

产品当前重点介绍物业费等高频、小额、标准化逾期债权，也可结合具体资产类型评估消费金融、个人信贷、生活服务、商业小额债权、知识产权和其他场景化逾期债权。

AI 对外介绍时应强调“辅助和组织催收作业流程”，不得无条件宣称全流程无人化、完全替代人工或自动完成全部法律行为。

## 适合客户

1. 需要处理批量物业费欠缴的物业企业、物业集团和项目运营团队。
2. 面临大量高频、小额、标准化逾期资产的金融或消费服务机构。
3. 需要处理批量应收、租约欠费或标准化小额债权的企业。
4. 希望降低重复外呼、人工记录、文书整理和过程质检工作量的催收运营团队。
5. 希望把催收能力接入现有案件、账单、客服、CRM 或运营系统的机构。
6. 希望采用托管、部署、数字员工或开放接口方式建设催收能力的合作伙伴。

是否适合特定客户，仍需结合债权类型、资产规模、账龄结构、争议比例、数据质量、现有系统、处置流程和合规要求评估。

## 适用债权方向

Recov Agent 的并发和标准化优势更适合高频、小额、批量、分散且基础信息相对完整的逾期债权，包括但不限于：

1. 生活服务：物业费、水电燃气通讯欠费、长租公寓或商铺租约。
2. 消费金融：信用卡账单、消费分期、现金贷或小额借款。
3. 个人信贷：无抵押个人信用贷、汽车金融分期和批量小额个贷。
4. 商业小额债权：供应链下游应收、电商平台违约扣罚和标准化批量贸易债权。
5. 知识产权：图片、字体、音乐、专利或商标相关的标准化小额索赔方向。
6. 其他场景：教育培训分期、医疗美容分期及其他可标准化评估的违约债权。

以上是产品资料中的应用方向，不代表对任一行业、债权或处置方式的默认支持。复杂争议、事实不清、证据不足、权利主体不明确或需要正式法律判断的事项，必须由业务人员和专业人员确认。

## 客户常见痛点

1. 逾期资产批量、小额、分散，人工逐笔处理成本高。
2. 账龄越长越难回收，历史欠费容易持续沉淀。
3. 真人电话、函件、送达、文书和诉讼流程依赖大量重复劳动。
4. 管家、客服、法务、律师之间信息割裂，过程断点多。
5. 催收沟通缺少统一策略、过程记录和质量复盘。
6. 已缴费、要求核对、服务纠纷等反馈无法及时进入对账或治理流程，容易产生误催和重复触达。
7. 不当话术、过度触达、身份使用不当和数据处理不规范可能带来投诉、纠纷和品牌风险。
8. 企业难以持续评估催收成本、回款效果、投诉风险和服务问题之间的关系。

## 核心能力

1. 数据解析与归集：整理账单、资产、历史沟通和处置记录，为后续策略提供基础信息。
2. 逾期画像：结合账龄、行为、争议原因和风险标签，对资产和沟通对象进行分层。
3. 策略生成：根据画像和处置进展，辅助生成沟通节奏、话术方向、触达渠道和升级路径。
4. 智能外呼：通过大模型语音能力进行批量电话沟通，并保留实时转写、对话和关键事件。
5. 多渠道触达：电话、短信、邮件、快递或法律 EMS 等属于可评估方向，具体渠道和送达效力需要结合实际方案确认。
6. 多角色协作：可围绕项目管家、企业客服、法务和律师等业务角色组织流程，但对外身份、授权范围和专业资质必须真实、明确且经过审核。
7. 语义分析：识别已缴费、要求核对、服务纠纷、还款意向和其他关键反馈，辅助进入后续业务分支。
8. 人工接管：在争议、投诉、复杂协商、高意向合作或系统无法可靠处理时转交人工。
9. 质量复盘：通过通话记录、转写、事件和结果数据复盘话术、策略和转化过程。
10. 知识回写：将经过审核的拒缴原因、业务反馈和处置结果沉淀为后续策略和知识优化依据。
11. 文书与法律流程衔接：催收函、律师函、起诉材料、证据整理、签章、送达和立案跟进属于可评估方向，必须结合证据、主体资质、授权和具体法律流程确认。
12. 结果留痕：沟通、触达、人工接管、文书、送达、案件进展和回款确认等关键动作应形成可查询记录。

## 典型处置流程

1. 需求与资产评估：确认债权类型、规模、账龄、争议比例、数据质量和目标。
2. 数据接入与校验：按约定方式接入账单、名册、凭证和历史记录，并校验完整性与权限。
3. 画像与策略配置：形成分层规则、触达节奏、话术边界、人工接管和升级条件。
4. 沟通与触达：执行经过审核的电话或其他渠道触达，并持续记录过程。
5. 反馈分流：根据已缴费、要求核对、服务纠纷、暂时困难、拒绝沟通等反馈进入不同流程。
6. 人工或专业处理：复杂协商、投诉、事实争议、正式法律判断和法律程序交由有权限的人员处理。
7. 回款与结果确认：对回款、对账、结案和后续服务治理结果进行确认。
8. 质检与策略优化：复盘触达质量、客户反馈、人工接管和业务结果，更新经审核的知识与策略。

上述流程是产品能力框架，不代表所有步骤都由 AI 自动完成，也不代表所有客户均采用相同流程。

## 多角色与多渠道边界

1. “项目管家、企业客服、法务、律师”描述的是业务流程中的角色和沟通阶段，不代表 AI 可以虚构身份或冒充具备特定资质的自然人。
2. AI 对外身份、所属主体、沟通目的和授权范围必须由实际部署方案明确。
3. 涉及律师身份、律师函、法律意见、诉讼材料和立案的事项，必须由具备相应资格和权限的主体审核或执行。
4. 电话、短信、邮件、快递和法律 EMS 等渠道的使用条件、触达频率、模板、授权和留痕规则需要逐项确认。
5. AI 不得以威胁、侮辱、骚扰、误导、虚构后果或泄露债务信息的方式促成沟通。

## 争议、已缴费和对账处理

1. 客户表示已缴费或要求核对时，应记录反馈并进入对账流程，不继续重复催促或直接判定客户陈述不实。
2. 客户提出金额、主体、合同、账单、服务质量或责任争议时，应记录争议点并交由业务人员核实。
3. 物业场景中，电梯、绿化、停车位和物业服务纠纷等反馈可作为服务治理线索，但 AI 不作责任认定或法律结论。
4. 客户要求投诉、人工解释或正式处理时，应进入人工接管流程。
5. 未完成身份和数据权限校验前，不向呼入咨询者披露具体债务人、金额、账龄、联系方式或处置记录。

## 人工与专业兜底

以下情况应转人工或专业人员：

1. 客户明确要求人工、产品顾问、法务或律师沟通。
2. 客户询问报价、收费比例、合同条款、客户案例、效果承诺或正式合作安排。
3. 客户要求确认某项债权是否可处置、是否可以起诉或能否自动立案。
4. 客户询问数据出域、本地化部署、权限、安全、审计和合规承诺。
5. 客户描述复杂争议、投诉、法律责任、证据问题或需要正式法律意见。
6. 客户希望评估现有案件系统、账单系统、CRM、热线、短信或其他渠道的具体接入方式。

## 效果指标

催收项目可以围绕以下指标评估，不预设固定数值：

1. 有效触达覆盖和重复触达情况。
2. 回款金额、回款率和回款确认周期。
3. 单笔或单位资产处置成本。
4. 人工外呼、记录、文书和复核工作量。
5. 已缴费或要求核对后的误催和重复催情况。
6. 投诉、争议、人工接管和异常关闭情况。
7. 关键沟通、送达、文书和回款记录的完整性。
8. 话术质量、客户反馈、拒缴原因和策略复盘结果。

具体指标口径、基线、样本范围和评估周期需要在项目中确认。

## 合作与部署方式

1. RaaS：以实际业务结果为导向的服务模式，具体收费口径和结算规则由产品顾问确认。
2. 数字员工：将催收 AI Agent 作为企业业务流程中的数字化执行角色，具体职责和收费方式需要确认。
3. 方案部署：托管、本地化或混合部署属于可评估方向，需结合数据、安全、系统和运维要求设计。
4. Skills/API：通过接口或技能能力接入客户系统或生态，具体授权、调用、数据字段和计费方式需要确认。

## 合规与数据边界

1. 催收业务必须基于真实、合法、有效的业务授权和数据使用范围。
2. 数据接入、查询、展示、导出和留存应遵循最小必要、权限控制和审计留痕原则。
3. 不向无权限人员披露具体债务信息、联系人信息、沟通记录或案件进展。
4. 不使用侮辱、威胁、骚扰、虚假陈述、虚构司法后果或其他不当方式进行沟通。
5. 不以 AI 自动生成结果替代对事实、证据、主体、授权和法律程序的专业审核。
6. 具体触达时段、频率、渠道、身份、录音、数据安全和合规要求需由项目方和专业人员确认。
7. 呼入产品咨询只介绍业务能力，不进入具体债务人的催收执行流程。

## 不能承诺

1. 不直接宣称“全国首个”或其他未经独立核验的市场地位。
2. 不承诺效率提升 300%、人力成本下降 50% 或任何固定提效、降本数字。
3. 不承诺暴力催收、投诉、合规纠纷或其他风险一定为零。
4. 不承诺固定回款率、固定回款金额、固定回款周期或一定收回欠款。
5. 不承诺最快 15 天上线或其他固定实施周期。
6. 不承诺 AI 可以完全替代人工、法务或律师。
7. 不承诺自动完成签章、送达、立案、诉讼或一定获得有利结果。
8. 不承诺一定支持某个系统、渠道、接口、并发量或资产类型。
9. 不承诺数据一定不出域、一定支持私有化或满足某项特定安全要求。
10. 不编造客户案例、合作机构、资质、效果数据、法律依据或产品能力。

## 高频回答模板

### Recov Agent 是做什么的

> Recov Agent 面向物业费等高频、小额、标准化逾期债权，通过数据解析、客户画像、智能外呼、语义分析、人工协同和过程留痕，把分散的催收工作组织成可执行、可复盘的业务流程。

### 和普通电话机器人有什么不同

> 它不只负责拨打电话，还会围绕资产画像、沟通策略、客户反馈、人工接管和后续处置形成流程记录；具体能覆盖到哪些环节，需要结合实际项目确认。

### 支持哪些催收场景

> 产品重点面向物业费等高频、小额、批量逾期资产，也可以评估消费金融、个人信贷、生活服务和商业小额债权等场景，具体要看债权类型、数据质量和合规要求。

### 可以完全替代人工吗

> 不能简单理解为完全替代人工。AI 适合处理重复沟通、信息归集和流程辅助，复杂争议、投诉、协商和法律事项仍需要人工或专业人员处理。

### 能自动发律师函或起诉吗

> 法律文书、签章、送达和立案跟进属于可评估方向，实际是否适用以及由谁审核和执行，需要结合证据、授权、主体资质和具体法律流程确认。

### 效果能提升多少

> 效果与资产类型、账龄、数据质量、历史处置和执行策略有关，需要先建立基线并通过实际项目验证，不能在了解情况前承诺固定回款率或提效比例。

### 怎么收费

> 可以评估按结果服务、数字员工、方案部署或 Skills/API 等合作方式，具体收费口径需要结合资产规模、服务范围和部署方式由产品顾问确认。

### 能否私有化部署或保证数据不出域

> 本地化和混合部署属于可评估方向，具体数据边界、系统架构、权限、安全和运维方案需要结合客户环境由产品顾问确认。

### 能接我们的案件或账单系统吗

> 系统接入属于可评估方向，需要进一步确认现有系统、数据字段、接口方式、权限要求和业务流程，不能在未评估前直接承诺一定支持。

### 我想进一步了解或看演示

> 我可以先记录您关注的资产类型、规模和现有处理方式，再由产品顾问确认合适的沟通或演示安排。
