# 通话结束归因

2026-09-22，本地实现及验证，尚未发布。

## 业务与接口

通话记录新增只读 `endCategory`，列表、记录详情、回拨详情共用展示函数。
原始 `endReason`、故障信息、SIP 接通事实和时长保持独立，不修改历史数据库记录。

| 值 | 显示 | 依据 |
| --- | --- | --- |
| `agent` | 坐席挂断 | 已鉴权的人工结束动作 |
| `customer` | 客户侧挂断 | 匹配本通话客户身份的主动断开证据 |
| `system_normal` | 系统正常结束 | AI 完成任务、客户口头要求结束、平台结束策略 |
| `system_error` | 系统异常结束 | 模型、音频、运行服务、连接等明确异常 |
| `unknown` | 原因未确认 | 缺少依据或只有笼统的参与者离开原因 |

进行中的记录没有结束依据时返回 `null`。前端保留有用的具体原因；
`customer_end` 表示 AI 执行客户的口头要求，归为系统正常结束。
客户侧断开不等于证明手机按键挂断，也可能由客户侧网关发起。

历史 `sip_participant_left` 只在首条终止证据的租户、通话、房间及客户身份匹配时细分。
SIP `CLIENT_INITIATED` 还要求 SIP 类型和已接通事实；后续清理证据不能改变首因。
旧 `remote_hangup` 曾笼统记录任意离开事件，缺少进一步证据时保留未确认。
后续旧版 SIP 入口及人工回拨使用 `sip_client_initiated` / `sip_transport_error` 保留明确原因。

仓库部署配置使用 LiveKit SIP v1.5.0。核对了其
[远端 BYE 处理](https://github.com/livekit/sip/blob/v1.5.0/pkg/sip/client.go#L319-L335)
与 [SIP 退出处理](https://github.com/livekit/sip/blob/v1.5.0/pkg/sip/outbound.go#L227-L255)。
分类只表达平台可见的结束来源，不额外推断运营商内部动作。

## 终态与并发

- Owner 坐席结束接口在事务内登记 `END_CALL`，记录操作人和时间；后台清理复用原去重键。
- 坐席认领、媒体就绪、结束、旧版结束及管理员修复统一先锁通话，再锁交接、坐席状态。
- 人工回拨结束和客户离开均锁定并刷新通话记录，清理前固定原因。
  迟到 Webhook 遇到终态直接返回，包含响铃阶段已被坐席结束的情况。
- 使用现有终态屏障、去重和清理重试，不引入新表、定时任务或生产数据回填。
