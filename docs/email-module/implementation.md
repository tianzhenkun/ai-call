## 配置和启动

邮件 API 和 worker 均沿用现有 `DATABASE_*`、文件存储配置。启动前核对 Release 启动服务的进程环境：进程环境变量优先于 env 文件，不能仅看 `.env.dev` 推断实际数据库。

在 REACH 后端原有本地配置中加入 `config.example.env` 的配置项。该文件只是无密钥示例，不自动加载。

- `REACH_EMAIL_ENCRYPTION_KEY`：稳定的 Fernet 密钥，用于邮箱授权码加密。与 Java 密文不互通，也不需要迁移旧密文。备份后长期使用，不能每次启动重新生成。
- `REACH_EMAIL_LLM_API_KEY`：DeepSeek API Key。只用于邮件 AI，不改变通话模型。
- 对应 `*_FILE` 是 UTF-8 文件路径。直接值与文件引用只能选一种，同时配置会明确报错；不输出密钥。
- `REACH_EMAIL_LLM_MODEL` 默认 `deepseek-v4-pro`；需由实际账户/API 调用验证可用性，当前未进行外部模型调用。
- 配置变更需重启读取该配置的 API 和邮件 worker。不要停止 19011/19012 的独立外呼测试进程。

从当前 ai-call 仓库、载入与 API 相同的部署环境后执行：

```bash
# 先列出目标表，不执行数据库变更
ENVIRONMENT=dev .venv/bin/python -m app.services.reach_email.migrate
# 核对数据库后，首次建表；仅创建邮件表，不改其他业务表
ENVIRONMENT=dev .venv/bin/python -m app.services.reach_email.migrate --apply
# 单独终端/部署服务运行邮件 worker（不会启动外呼 worker）
ENVIRONMENT=dev .venv/bin/python -m app.services.reach_email.worker
```

迁移是本期新表初始建表入口，`checkfirst` 不会升级已经存在的旧表；未来改变表结构需单独增量迁移。API 继续由现有 Release 服务启动；前端继续使用原有 web-reach 服务。新增 worker 需单独纳入启动编排，当前未修改 release 仓库。

平台菜单登记值：名称“邮件管理”，页面路径 `/reach/email`，组件 `reach/email/index`，产品 `reach`；按现有平台菜单管理流程分配相应角色及租户套餐。不能借用 Sales 菜单。网关继续走 `/reach-api/v1/email/*`。

## 发送记录统计口径（2026-09-17）

- 一个任务一行；发件邮箱汇总可打开各邮箱明细。筛选邮箱命中任务后，仍返回该任务全部邮箱统计，避免部分数据冒充任务总计。
- 发送邮件数：尝试发送过的出站邮件数；重试不重复计数。收到回复数：已关联任务的客户来信封数，不含新同步的自动回复和 DSN；同一封原邮件收到多次回复时，送达只计一次。
- 已确认送达数：明确对应原邮件的客户回复、来自原收件人的自动回复，或 `Action: delivered` 且 `Status: 2.x` 的 DSN。按原邮件去重，校验账号、邮件编号和收件人；有冲突的失败证据不计成功。中转、延迟通知不算送达。自动回复不计入客户回复数，仍按原计划跟进，不识别返岗日期或自动延期。
- 失败数：发送终止失败或明确关联原邮件及收件人的永久退信。其余已尝试邮件计入未确认，三项总和等于发送邮件数。未确认不表示未送达。
- SMTP 服务支持 DSN 时请求成功、失败、延迟通知及原邮件头；不支持时正常发送。协议语义参考 [RFC 3464](https://www.rfc-editor.org/rfc/rfc3464) 和 [RFC 3461](https://www.rfc-editor.org/rfc/rfc3461)。服务商是否提供回执仍取决于其能力，不能保证每封邮件都获得最终确认。
- 升级前执行邮件迁移命令，补齐 `reach_email_message.delivery_report`；同步进程需重启。已有明确回复关联可直接参与统计，历史未保存的 DSN 信息不能凭空补齐。
